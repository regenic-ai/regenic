# 个人搜索

- **相关：** [桌面端](DESKTOP.md) · [对话上下文检索 MCP](CONTEXT_SEARCH_MCP.md) · [执行器](EXECUTOR.md)
- **状态：** 桌面已按本方案拆成精准与问答。问答通过执行器会话调用精准搜索 MCP。

搜索是一个功能，侧栏只有「搜索」一个入口，⌘K 打开同一页。页顶居中是分段：**精准**、**问答**；精准侧右上角是「本地语义搜索」设置入口。两边不共用查询和结果。

精准搜索按名称或内容定位消息与文件，点进原会话。对话上下文检索 MCP 是这套检索的工具形式。

问答是页内的一条对话：左侧是过去的问题，右侧是消息，输入框钉在底部。创建时挂上精准搜索 MCP，执行器自己调用工具。它不使用工作台的会话头（置顶、隐藏、转发）。

工作台会话的标题栏有两个图标：查找（⌘F）和问问这条会话。查找在标题下方展开一条查找条，不盖住消息。边输入边查，范围锁在当前会话，命中的原文高亮，当前这条消息的图片也套上标记。上一处 / 下一处按时间走，从当前视野开始。问问这条会话打开搜索的问答，输入框里带一枚可去掉的范围标签。

## 组件

| 组件 | 用在哪里 | 呈现 |
| --- | --- | --- |
| 精准搜索 | 搜索页的精准分段 | 查询框、筛选芯片、命中列表 |
| 会话内查找 | 工作台会话标题栏的查找图标、⌘F | 标题下方的查找条。计数、上一处 / 下一处、关闭。原文高亮，当前消息的图片有标记 |
| 问答对话 | 搜索页的问答分段 | 空状态（输入框 + 示例问题）、问题栏、气泡、底部输入框、查阅活动 |

| 挂载位置 | 行为 |
| --- | --- |
| 搜索页 · 精准 | 筛选可改。点命中后在工作台打开原会话 |
| 搜索页 · 问答 | 执行器创建时挂上 MCP，自己调用精准搜索工具 |
| 工作台 · 查找 | `thread_id` 锁死。点上一处 / 下一处滚动到该消息 |
| 工作台 · 问问这条会话 | 打开问答，下一次提问的工具范围锁在这个 `thread_id` |

## 搜索页

页顶居中是分段：**精准**、**问答**。记住上次停留的分段。切换分段不携带输入框里的文字，也不携带另一边的结果。

| | 精准 | 问答 |
| --- | --- | --- |
| 第一屏 | 搜索框、筛选、最近的原文查询 | 居中的标题、输入框和三条示例问题；有过问题时左侧出现问题栏 |
| 提交之后 | 命中列表 | 用户问题成一条气泡。查阅活动出现在回答上面 |
| 再查一次 | 替换这次命中 | 底部输入框继续问同一条 |
| 留下的记录 | 这一侧的最近搜索 | 左侧的问题列表 |

### 精准

用户输入名称、关键词，或记得的原句。组件按词语匹配；开启本地语义搜索后，同时按含义匹配。筛选只在这一侧可改：

| 筛选 | 取值 |
| --- | --- |
| 范围 | 全部、消息、文件 |
| 应用 | 普通应用（默认）、Agent 应用、全部应用 |
| 其他 | 来源（已连接的应用，按名字选）、会话（按会话名选）、显示条数 |

结果是命中列表：高亮片段、时间、来源和文件身份。「查看原消息」按 current 生命周期、授权和 Event / hash 重新检查后，再跳回原会话。词法或混合检索、向量覆盖、降级和截断显示在这一侧。

最近搜索只记录这里提交过的查询，例如人名、文件名和原句。空状态的例子也只保留这些。本地语义搜索的开关留在设置里。

这一侧直接调用检索接口。在精准框里输入统计或汇总句子时，仍按精准搜索执行。

### 问答

左侧是问题列表，右侧是对话，输入框钉在底部。统计、汇总、列举和模糊回忆都在这里完成。问答不复用工作台会话头。

新问题从底部输入框发出，创建会话并挂上 `regenic-context`（`POST /v1/agent/context/mcp`）。输入框左下角是当前 Agent，点开后切换，交互和选择模型一样。只列出已启用、且能自己挂上上下文工具的 Agent。标题用这条消息。继续问留在同一条对话里，沿用这条对话原来的 Agent。

从某条会话点「问问这条会话」进来时，标题带上那条会话的名字，工具范围锁在它的 `thread_id`。执行器不能把范围放宽到其他会话。

执行器读取个人上下文时只走精准搜索 MCP：

1. 自己决定查询词、范围和应用类型，调用 `search_conversations`。范围已被锁住时，沿用锁住的 `thread_id`。
2. `truncated` 为真、且省略部分会影响结论时，用同一 `read_epoch` 调用 `read_conversation_window`。
3. `read_epoch` 过期则重新搜索，不把新旧窗口写进同一次结论。
4. 回答用会话名和时间说明事实。`event_id` 留在工具结果里，不写进正文。

每一次查阅是线程里的一行活动，默认收成一句：查询词和命中数。展开后看到续读了哪一段。点引用在工作台打开原会话；问题列表仍留在问答侧。证据只来自该会话里实际返回的窗口。

取证默认 `app_class=app`。先前的问答会话不作为业务原文。一次 `search_conversations` 最多 20 条有界命中。截断时先续读再回答；仍然读不完时，用一句话说明缺了什么。对话里不展示 “Still working” 和渠道的系统提示，只留问题和回答。查阅次数收在回答上方。

没有可挂 MCP 的执行器时，问答侧说明当前不能提问。精准侧保持可用。

## 会话内

会话标题栏、上一条 / 下一条左边有两个图标。

**查找**（⌘F）在标题下方展开查找条，不盖住消息。`thread_id` 固定为当前会话，普通应用和 Agent 会话都查这一条。停止输入 300ms 后按输入的原文查询，不把「最近一个月」这类说法改成时间范围。命中按时间排序，从当前视野里的第一处开始；回车下一处（更晚），Shift+回车上一处（更早），Esc 关闭。命中不在已经加载的消息里时，先把那一页拉进会话再跳过去。原文里的查询词用暖黄标出，当前这一处更深，气泡本身也有一圈暖黄描边；当前消息里的图片同样套上这圈描边。人留在这条会话里。

**问问这条会话**打开搜索页的问答。输入框里显示可去掉的范围标签，示例问题换成针对单条会话的问法，下一次提问锁在这个 `thread_id`。原渠道线程不增加消息，会话底部的输入框仍然发回原渠道。

## 精准搜索 MCP

MCP 是精准搜索组件的工具形式。搜索页的精准侧、会话内的查找，以及问答里的执行器，调用同一套只读工具。配置、凭据和参数见[对话上下文检索 MCP](CONTEXT_SEARCH_MCP.md)。

| 工具 | 行为 |
| --- | --- |
| `search_conversations` | 检索已授权文本，把命中扩展为有界对话窗口，并返回文件命中。`limit` 最大 20。可带 `thread_ids` 把范围锁在会话内 |
| `read_conversation_window` | 用同一次结果的 `read_epoch` 续读前文、后文或缺口 |

返回保留 `event_id`、`content_hash`、`read_epoch`、`truncated` 和 `continuation`。`read_epoch` 过期时拒绝续读，调用方重新搜索，不把新旧窗口拼在一起。默认 `app_class` 为 `app`，Agent 和执行器会话不进入结果。

这些工具只返回定位和窗口。它们不写摘要，不做统计，也不发起对话。

## 范围外

- 精准侧不挂执行器，也不再提供「让执行器回答」。
- 问答不把工具命中写入精准侧的结果或最近搜索。
- 问答会话不出现在工作台的渠道列表里。
- 渠道会话的 Composer 不接受提问，也不在原渠道线程里插入查阅活动。
- 精准搜索 MCP 不增加汇总或统计工具。
- 问答里的上下文工具保持只读：不发送消息、不修改文件、不批准草稿。

## 当前实现

精准搜索在 `PreciseSearch`，只出现在搜索页的精准分段。会话内查找是 `ThreadFindBar`，只在当前会话里上一处、下一处。问答是搜索页里的对话，不挂工作台会话头。精准侧不再提供「让执行器回答」。

问答在搜索页的另一分段。提交后创建目的为 `search-question` 的执行器会话，`include_context` 打开，从而挂上 `regenic-context`。范围锁在 `executor_config.search_thread_id` 时，MCP 的 `search_conversations` 和 `read_conversation_window` 不能改到其他会话。问题列表记在本机；执行器会话不进工作台列表。追问使用同一条执行器线程上的会话组件，不因输入框旁换成另一个 Agent 而改道。这条问题完成后的 24 小时内，追问仍可调用上下文工具；其他已结束的执行不能。
