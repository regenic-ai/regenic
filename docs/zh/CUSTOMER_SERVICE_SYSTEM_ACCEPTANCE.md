# 客服系统级验收

Regenic 提供一条客服集成边界的黑盒验收路径。它会启动真实的客服 MCP stdio 服务，调用 Personal API，通过 Context Engine 读取证据，并查询受控业务 HTTP 服务。

运行命令：

```powershell
pnpm --filter @regenic/api eval:customer-service-system
```

该命令会构建 MCP 客户端和 API 依赖图，执行验收用例，输出稳定的 JSON 报告；任何合同断言失败都会以非零状态退出。

## 覆盖场景

| 场景 | 必须保证的行为 |
|---|---|
| 正常回答 | 通过 MCP 创建任务、找回全部必要对话证据、提交证据绑定的 brief、精确查询两位稳定业务身份，并生成对客草稿。 |
| 人工审核边界 | MCP 不暴露审核或发送工具；批准只能经过受信任的 Personal API 边界。 |
| 业务事实变化 | 批准后业务记录版本变化必须阻止发送、清除旧批准，并把任务退回核验状态。 |
| 业务无记录 | `not_found` 不能支持“该成员尚未回复”的结论；草稿必须被拒绝且不能进入已批准状态。 |
| 内部字段 | `visibility: internal` 的字段不能支持对客结论；草稿必须被拒绝且不能进入已批准状态。 |
| 查询范围 | 每次业务请求都必须使用已核验的客户、项目、批次、成员 ID 和请求字段。 |

报告不会把随机 task/query ID 或耗时写入内容哈希。

## 与确定性门禁的关系

[客服场景评测门禁](./CUSTOMER_SERVICE_EVALUATION.md)使用 60 条确定性工作流用例度量检索与安全指标。本验收集规模更小，专门证明相同的关键合同能够穿过真实接口边界：

```text
MCP stdio -> Personal API -> Context Engine -> 受控业务 HTTP 服务
```

两套检查都需要保留。系统级验收不能替代 60 条工作流回归集，工作流回归集也不能证明 MCP/API 集成正确。

## 限制

本验收使用合成连接器 Event 和 oracle 提供的工具参数，不代表已经验证：

- 真实 Cursor 会话中的模型推理或提示词质量；
- 生产连接器同步完整性；
- 真实租户授权和披露策略；
- 生产业务服务；
- 延迟、并发或容量。

这些声明仍需使用已授权的生产近似连接器、受限业务测试服务、真实目标 Cursor/MCP 客户端和单独治理的保留确认集完成复验。
