# 产品定位

- **English:** [../en/PRODUCT.md](../en/PRODUCT.md)
- **相关：** [路线图](ROADMAP.md) · [从个人到组织](rfcs/personal-to-org.md) · RFC 0001–0007

## 1. Regenic 做什么

Regenic 帮个人和组织**处理已经产生的信息**。

聊天、邮件、工单、文档、指标本身不由 Regenic 产生。Regenic 负责把它们
接进来（主动拉取或被动推送），再过滤、分层、提炼事实，并支撑判断标准的修订，
让人和 Agent 能在同一套标准、同一份上下文里做决定。

常见加工步骤：

| 步骤 | 说明 |
| --- | --- |
| 接入 | 连接器：Webhook、轮询、文件导入、Agent 回合等 |
| 过滤 | 去掉噪音，遵守权限与个人边界 |
| 分层 | 按耐久与敏感程度存放（Event / Blob / Digest / Standard） |
| 提炼事实 | 形成有出处的 Claim、Digest，以及「现在该关注什么」 |
| 修订标准 | 发现缺口 → 提案 → 版本化的判断标准（RFC 0001） |
| 行动与跟进 | 待办队列、交接、未回复跟进等——都是加工之后的用法 |

收件箱整理、「该知道什么」、未回复排序等，都是上述管道上的具体功能，
不是产品定义本身。

## 2. 双能力模型

来自《重写基因》：

1. **判断标准** — 把人与 Agent 共用的标准写清楚、用起来、改得动  
2. **统一上下文** — 同一决策看到同一组事实，并知道事实从哪来  

Regenic 的工作，就是把各渠道里的原始信息，加工成这两项能力用得上的材料。

## 3. 先个人，后组织

| 阶段 | 范围 |
| --- | --- |
| **个人（当前）** | 一个使用者；数据默认在本地 |
| **组织（其后）** | 多人场景下的权威事件与各人视角 |

先做个人：一个人就能把接入 → 加工 → 行动跑通。  
组织阶段沿用同一套对象模型，再补上身份、策略，以及「同一条消息只认一次」的合并规则。详见 [从个人到组织](rfcs/personal-to-org.md)。

## 4. 个人版原则

1. **本地为准** — 本机或自托管库是权威，不以远端默认为准。  
2. **历史可远端、默认关闭** — 用户自己决定是否把冷数据放到远端；那不是组织库。  
3. **导出开放** — Markdown / JSONL，数据能带走。  
4. **接入可插拔** — ChannelConnector，拉取与推送同等对待。  
5. **不做笔记软件** — Phase 1 不做大纲笔记或双向链接知识库内核。

## 5. 近期不做

- 取代飞书 / Slack / 邮件当聊天工具  
- 做成通用知识库或文档套件  
- 通用 ERP（人事、财务等）  
- 把个人侧的 AI 标签，不经组织侧加工就当成组织事实
