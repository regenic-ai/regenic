## 概述

Regenic 是个人与组织的消息编排层。

它不生产聊天、邮件、工单、文档或帖子。它们仍在被写下的渠道里。Regenic 接入这些流量。一天里群消息可能有几千条。判断标准和各人习惯把其中需要处理的送进人与 Agent 共用的**消息控制台**，其余的不进入当前工作。出现重大异常，或一条消息已经进入手头流程时，它仍会到达控制台。回复发回原渠道。

权限与判断标准留在内核。

Regenic 位于已有对话与 Agent 工具之下，作为证据与加工层。详见[协作平台集成架构](CONTEXT_PLATFORM_INTEGRATION.md)。

| 步骤 | 说明 |
| --- | --- |
| 接入 | Slack、邮件、工单、文件、Agent 回合 → 同一种消息 |
| 过滤 | 去掉噪音，遵守权限与个人边界 |
| 分层 / 排序 | 按耐久、敏感、「该知道」存放（Event / Blob / Digest / Standard） |
| 提炼 | 有出处的 Claim、Digest、跟进信号 |
| 调度 | 按版本化标准和各人习惯：需要处理的进入控制台，其余不进入当前工作 |
| 发送 | 回复发回原渠道 |
| 修订标准 | 发现缺口 → 提案 → 版本化的判断标准（RFC 0001） |

## 能力

1. **判断标准** — 编码、应用并修订排序与调度规则
2. **统一上下文** — 同一决策看到同一组事实，并带有出处

渠道流量为这两项进料。方法来源：[regenic-ai/regenic-book](https://github.com/regenic-ai/regenic-book)。

## 先个人，后组织

| 阶段 | 范围 |
| --- | --- |
| **个人（当前）** | 一个使用者；权威在本机 |
| **组织（其后）** | 多人场景下的权威事件与各人视角 |

先交付个人，使单人能接上一个渠道、完成调度，并可选择回复。组织沿用同一种消息格式。详见 [从个人到组织](rfcs/personal-to-org.md)。

## 个人版

1. **本地为准** — 本机或自托管库是权威。
2. **历史可远端、默认关闭** — 冷备份由使用者打开；那不是组织库。
3. **导出开放** — Markdown / JSONL，数据可迁移。
4. **渠道仍在原处** — Slack 还是 Slack。Regenic 从这些应用读取并写回，不取代它们。
5. **不是笔记产品** — Phase 1 不含大纲笔记或双向链接知识库。
6. **控制台是工作台** — 默认展示当前需要处理的，不是所有渠道的瀑布流。

## 范围外

- 取代已经在写消息的那些应用
- 通用知识库或文档套件
- 通用 ERP 模块
- 把个人侧的 AI 标签，不经组织侧加工就当成组织事实
- 重做别人的消息工具、Studio、公共 feed 或模型路由
- 没有标准与上下文约束的无界 Agent 循环
