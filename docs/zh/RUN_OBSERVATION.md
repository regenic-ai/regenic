# 执行观测

- **English:** [../en/RUN_OBSERVATION.md](../en/RUN_OBSERVATION.md)
- **相关：** [个人搜索](SEARCH.md) · [桌面端](DESKTOP.md) · [执行器](EXECUTOR.md) · [RFC 0009](rfcs/0009-work-orchestration.md)
- **状态：** 设计。桌面尚未按本文改观测界面。

执行观测是桌面端呈现一次 Agent 执行的方式。每次执行都画成同一张**运行卡片**：先给结论和动作，再给用时，过程按需展开。工作台会话、自动化编辑器和搜索页的问答复用这张卡片，只是放的位置不同。

## 观测要回答的问题

用户打开一次执行，依次想知道下面五件事。卡片的顺序按这个排，前两件不用点开就能看到。

| 顺序 | 问题 | 卡片上回答它的部分 |
| --- | --- | --- |
| 1 | 它得出了什么结论？ | 结论 |
| 2 | 它替我做了什么，还要我做什么？ | 动作行 |
| 3 | 现在跑完了吗，正常吗？ | 状态与用时 |
| 4 | 它凭什么这么说？ | 过程：触发、任务说明、查阅 |
| 5 | 这条自动化总体靠不靠谱？ | 自动化页的健康行 |

## 现状

| 位置 | 现在显示 | 缺陷 |
| --- | --- | --- |
| 自动化 · 最近运行 | 每行是状态、时刻和一行截断的摘要，点整行跳到来源会话 | 摘要没有清洗，漏出 `REPLY`、`NOTE`、`feishu:oc_…` 和 `**`。每行都写「上次已完成」，但只有第一行是上次。等你回复也显示成「正在处理」。没有用时。读不到全文，点进会话后也只能看到当前这一次 |
| 工作台会话 | 标题下是「Agent 查阅了 N 次会话记录」，再下面是「处理结果」卡片 | 看不出结论是不是已经过时：截图里结论之后对方又说了「算了 我弄个」。没有用时，进行中也没有时钟。看不出这次有没有发回原会话。更早的处理看不到 |
| 搜索 · 问答 | 问题栏、气泡、查阅、思考中、底部输入框 | 每一答没有用时。查阅堆在整段对话顶部，分不清属于哪一问 |

问答的阅读顺序已经是对的：问题、查阅、回答，等待时也有明确的状态。另外两处改成同一种阅读顺序，问答补上用时。

## 原则

1. **先结论，后过程。** 第一眼看到结论和动作，查阅和任务说明折起来。
2. **一个组件，三个位置。** 卡片在三处结构相同，宽度和密度可以不同。
3. **只显示人话。** 协议标记、内部 ID 和原始 Markdown 符号不出现在任何预览里。
4. **说清新旧。** 结论之后会话里有了新消息，就明说这条结论早于这些消息。
5. **说明下一步。** 失败、等你回复、没发出去这三种状态，都在同一行指出下一步去哪里处理。
6. **时间可信。** 只显示墙钟用时，不估算「模型在算」和「在等人」各占多少。

## 运行卡片

### 结构

```
┌──────────────────────────────────────────────────────────────┐
│ ● 已完成 · 用时 2 分 14 秒 · 昨天 17:46                  复制 │  状态行
│                                                              │
│ 本月该交的工资表已经交了。11 月 9 日方方在这里发了…          │  结论
│                                                              │
│ ↩ 已回复方方 · 已送达                                        │  动作行
│ ⚠ 这条结论早于会话里的 3 条新消息                             │  新旧提示（按需）
│ ▸ 过程 · 定时查看 · 查阅 5 次                                │  过程（折叠）
└──────────────────────────────────────────────────────────────┘
```

| 部分 | 内容 | 规则 |
| --- | --- | --- |
| 状态行 | 状态、用时、时刻；右侧放「复制」 | 状态同时用图标和文字表示，不只靠颜色 |
| 结论 | 清洗后的摘要正文 | 默认显示 3 行，超出时渐隐，加「展开全文」。展开后最高占面板 40%，超出部分在卡片内滚动 |
| 动作行 | 这次 Agent 回复了谁、发到没有，或为什么没有打扰对方 | 见「动作」。总是显示，只有没有结论时隐藏 |
| 新旧提示 | 结论之后会话里新增的消息数 | 只在工作台出现，见「新旧」 |
| 过程 | 触发方式、这次运行冻住的任务说明、查阅明细 | 默认折叠，摘要行写成「过程 · 触发方式 · 查阅 N 次」。查阅明细展开时才去请求 |

「复制」复制的是清洗后的正文，不含给你的备注。

### 正文清洗

所有预览和卡片都先经过 `workOperatorText`，这也是会话页现在的做法。之后再处理：

- **单行预览**（列表行、收起的运行、问题栏）：去掉 Markdown 标记，换行改成空格，按字符截断后加「…」。
- **会话 ID**（`feishu:oc_…` 这类）：不出现在预览里，也不出现在结论里。卡片里需要指出会话时，写会话名称。
- **备注**（`NOTE` 段）：不进结论正文，收在「过程」里，标题叫「给你的备注」。

### 动作

协议第一行的标记决定 Agent 是否回复。动作行据此写成：

| 情况 | 动作行 |
| --- | --- |
| `REPLY`，渠道已受理 | 已发送到「会话名」 |
| `REPLY`，账本写了已发送，但渠道没有受理 | 未发送，建议已保留 |
| `REPLY`，排队或发送中 | 正在发送到「会话名」… |
| `REPLY`，发送失败 | 发送失败 · 重试 |
| `REPLY`，送达未确认 | 送达未确认 · 核对 |
| `REPLY`，已受理，但结果写明还有消息没发出 | 已发送，部分消息未发出 |
| `QUIET` / `NO_REPLY` | 无需发送 |
| 规则不写回 | 仅作记录 |
| 等你回复 | 需要你回复 · 回复 |

「去会话…」「去回复」是链接。在工作台里它们滚到标题栏上现有的按钮或提示坞，不另做一套按钮。

## 状态与文案

三处共用同一套词。旧文案「上次已完成」「上次失败」只用于自动化列表卡片上的「上次」那一项，运行行里不再用。

| `WorkRun.status` | 标签 | 图标 | 色调 | 状态行示例 |
| --- | --- | --- | --- | --- |
| `running` | 处理中 | 旋转 | 进行色 | 处理中 · 已运行 38 秒 |
| `waiting_human` | 等你回复 | 暂停 | 提醒色 | 等你回复 · 已等 6 分钟 |
| `completed` | 已完成 | ✓ | 中性 | 已完成 · 用时 2 分 14 秒 |
| `failed` | 失败 | ✕ | 错误色 | 失败 · 用时 41 秒 |
| `cancelled` | 已取消 | – | 弱化 | 已取消 · 用时 12 秒 |

「已等」从进入等待开始算，但现在没有这个时刻。`waiting_human` 暂时写成「等你回复 · 已运行 6 分钟」；以后有了进入等待的时刻再改成「已等」。

## 时间

### 用时

| 执行 | 起点 | 终点 |
| --- | --- | --- |
| 一次运行（自动化、工作台） | `created_at` | 终态取 `updated_at`；未结束取现在 |
| 问答的一答 | 这条人话的 `occurred_at` | 下一条人话之前，最后一条助手消息的 `occurred_at` |

问答单独按「一答」算用时：同一条执行器线程上追问之后，运行的 `created_at` 到 `updated_at` 会包含两次提问之间的空档。

问答里的第一问，从人看到的那条问题算起，不从下发给执行器的任务提示算起。

### 写法

| 时长 | 写法 |
| --- | --- |
| < 1 秒（终态） | 不到 1 秒 |
| < 1 分钟 | 38 秒 |
| < 1 小时 | 2 分 14 秒 |
| ≥ 1 小时 | 1 小时 5 分 |

进行中按秒跳动；超过 1 小时后改成每分钟更新一次。数字用等宽数字，跳动时不让一行抖动。

### 时刻

用聊天时间的写法：今天写「17:46」，昨天写「昨天 17:46」，今年写「11/20 17:46」，更早的带年份。悬停显示含时区的完整时间。

### 比平时久

这条规则最近已结束的运行有 3 次及以上时，取它们用时的中位数。进行中的运行超过中位数的 3 倍、并且已超过 5 分钟，状态行改用提醒色，后面加一句「比平时久」。只提示，不自动停止。

## 新旧

只在工作台出现。结论之后，会话里又来了入站或出站消息（不算本次写回本身），就在动作行下面加一行：

> ⚠ 这条结论早于会话里的 3 条新消息

点这一行，消息列表滚到第一条新消息。这里只做比较：这次运行的 `updated_at`，与会话里已加载消息的 `occurred_at`。不发请求，也不重新跑。规则会因为新消息再开一张工单时，提示改写成「新消息已在处理」，并指向新的那一次运行。

## 工作台会话

卡片放在标题栏和查找条下面、消息列表上面，宽度与消息列一致。

默认收成一行：`✓ 已完成 · 昨天 18:59 · 2 分 14 秒 · 结论第一行… · 之后有 19 条新消息 ▾`。点这一行展开成完整卡片，状态行右侧的「收起」再收回。展开与否记在本机，换会话保持。展开后卡片最高 45% 窗口高度，超出在卡片内滚动，消息列表始终可见。下表描述展开后的卡片。

| 会话状态 | 卡片 |
| --- | --- |
| 进行中，还没有结论 | 状态行，下面是「过程 · 查阅 N 次」，再下面是一行「思考中」骨架。不画空的结论框 |
| 进行中，已有部分结论 | 结论照常显示，状态行仍写「已运行」 |
| 等你回复 | 卡片收成一行：`等你回复 · 已运行 6 分钟 · 依据 ▸`。提示坞照旧在底部；「依据」展开的是这次结论。整页只留一张厚卡片 |
| 已结束，会话可回复 | 完整卡片 |
| 会话已关闭 | 卡片移到列底，占现在结束态处理卡片的位置 |

### 更早的处理

同一工单上还有更早的运行时，卡片底部出现一行「更早的处理（2）▸」。展开是一列紧凑行，新的在上，不含当前运行：

```
✓ 已完成   11/20 17:07   1 分 2 秒    检查完了，结论是已提交，不需要催…
✕ 失败     11/19 09:12   40 秒        执行器没有退出…
```

点一行，在原位置展开成完整的运行卡片，人留在这条会话里。同时只展开一条。新头消息开出的是另一张工单，不出现在这个列表里。

### 收件箱行

收件箱行保持现在的一行预览（清洗后的结论第一行），不加用时。等你回复和失败继续用现在的关注标记。

## 自动化

### 位置

现在「最近运行」堆在编辑表单最上面，把「何时开始」挤到了首屏以下。改成：

- 编辑页顶部只留**健康行**和最近 3 条紧凑行，「全部最近运行（5）」放在末尾。
- 点任一行，从右侧滑出**运行详情面板**，里面是完整的运行卡片，过程默认展开。面板盖在表单上，不推动表单。Esc 或点面板外关闭。键盘 ↑ ↓ 在运行之间切换。
- 面板底部有「打开会话」，进入这次运行的来源会话。只有这个按钮会离开编辑页。

### 健康行

```
最近 5 次：4 次完成，1 次失败 · 通常 2 分钟左右 · 下次 12/9 09:00
```

| 片段 | 规则 |
| --- | --- |
| 次数 | 只统计接口返回的窗口（现在是 5 条）。有进行中的写成「1 次处理中」，有等你回复的写成「1 次等你回复」，等你回复排在最前 |
| 通常用时 | 已结束运行用时的中位数，取整到最接近的「秒 / 分钟」。终态少于 2 次时省略 |
| 下次 | 定时规则的 `next_run_at`。没有就省略 |

最近一次失败时，健康行用错误色开头：`最近一次失败 · 11/19 09:12 · 查看`。

### 紧凑行

```
✓  本月该交的工资表已经交了。11 月 9 日方方在这里发了…   已回复   昨天 17:46   2 分 14 秒  ›
```

每次运行一行，像表格一样对齐：状态图标、清洗后的结论（一行截断）、动作短语、时刻、用时。状态文字放在图标的悬停提示和读屏文本里。行间用细线分隔，整组外面一个圆角边框；「全部最近运行（5）」是边框内的最后一行。进行中的行，时钟在走，结论位置写「处理中…」。窄窗口隐藏动作和用时。

### 面板里的过程

| 项 | 内容 |
| --- | --- |
| 触发 | 收到新消息（附触发消息的第一行）/ 定时查看 / 手动开始 |
| Agent | 执行器名称 |
| 任务说明 | 这次运行冻住的任务正文，默认 2 行可展开。与编辑区当前的任务说明不同时，标出「此后已修改」 |
| 查阅 | 现在的查阅明细：时刻、查询词、条数 |
| 给你的备注 | `NOTE` 段 |

「此后已修改」解释了为什么同一条规则前后给出不同结论。这是排查自动化时最常问的问题。

## 问答

版式不变。每一答下面加上用时，查阅挪到所属的那一问下面。

| 位置 | 变化 |
| --- | --- |
| 思考中 | `思考中 · 12 秒`，计时跳动。回答出现或运行结束就停 |
| 助手气泡下方 | 一行弱化的元信息：`用时 1 分 8 秒 · 查阅 3 次 ▸`。点「查阅」原地展开这一问的查阅明细 |
| 查阅归属 | `read.at` 落在哪一问与下一问之间，就归哪一问。第一问之前的查阅归第一问。落不进任何一问的，归最后一问 |
| 失败且没有回答 | `这次没有完成 · 用时 41 秒 · 重新提问` |
| 问题栏 | 不显示用时。进行中的问题加处理中图标，失败的加错误点 |

问题栏是导航，加上用时只会添噪音，所以不放。

## 空状态与异常

| 情况 | 显示 |
| --- | --- |
| 自动化还没运行过 | 健康行写「还没有运行 · 下次 12/9 09:00」，旁边是「立即试跑」 |
| 运行结束但没有摘要 | 结论处写「Agent 没有留下结论」，用弱化色；动作行隐藏 |
| 失败 | 结论处显示当时记下的错误文本，前面加「失败原因」标签 |
| 已取消且没有摘要 | 只显示状态行 |
| 查阅加载失败 | 过程里写「查阅记录暂时读不到 · 重试」，不影响结论 |
| 运行的时间字段缺失（历史数据） | 不显示用时，其他照常 |

## 无障碍

- 跳动的计时不放进 `aria-live`。只有状态变化（开始、等你回复、完成、失败）才播报一次。
- 状态同时有图标和文字，色盲用户不靠颜色判断。
- 系统开启「减少动态效果」时，处理中图标不旋转，计时改成每 10 秒更新一次。
- 运行详情面板打开时焦点移到面板标题，关闭时回到原来那一行。

## 数据

`RecipeLastRun` 增加：

| 字段 | 来源 |
| --- | --- |
| `run_id` | `WorkRun.id` |
| `started_at` | `WorkRun.created_at` |
| `trigger_kind` | `WorkRun.trigger_kind` |
| `executor_type` | `WorkRun.executor_type` |
| `delivery` | 这次运行的写回状态（状态、写回、`last_error`），没有就省略 |

`at` 仍是 `updated_at`，`summary` 仍是完整的 `result.summary`。清洗和截断只发生在桌面端。

运行详情面板还要冻住的任务正文，以及触发消息的第一行。两者都在打开面板时按 `run_id` 取，不放进列表载荷。

工作台按这条会话的当前工单取运行列表（权威库已有 `listWorkRuns(org, work_item_id)`），每条带上面同样的字段。查阅仍按运行单独取。

问答用时来自线程里已有的消息时间，「新旧」比较的也是已加载的消息时间，都不新增字段。

## 范围外

- 观测不写回渠道，也不变成渠道里的消息。
- 运行详情面板和编辑页不提供输入框，不能在这里追问。
- 收件箱行不加用时。
- 不统计 token、费用和单次工具耗时。
- 不从墙钟里扣掉「等你」的时间。
- 「比平时久」只是提醒，不自动取消运行。
- 不改执行器收到的 `earlier_runs` / `history.md`。
- 精准搜索的「用时 n 秒」是检索请求耗时，与本文无关。

## 验收

不离开当前页面，用户应能：

- 在自动化编辑页首屏读到这条规则最近是否正常、通常用时多久、下次什么时候跑，并且不用滚动就能看到「何时开始」。
- 从任一运行行打开面板，读到全文结论、这次是否回复了对方、查阅了什么、当时的任务说明。
- 在工作台会话里判断这条结论是否早于最新消息。
- 在问答里看到每一答各自的用时和查阅。

同时满足：

- 任何预览里都不出现 `REPLY`、`NOTE`、`QUIET`、会话 ID 或原始 Markdown 符号。
- 等你回复和处理中在三处显示成两种状态。
- 进行中的运行三处都在计时，终态后停在用时上；「比平时久」按规则出现。
- 发送失败或送达未确认时，动作行有通往处理位置的链接。
- 屏幕阅读器不会每秒播报计时。
